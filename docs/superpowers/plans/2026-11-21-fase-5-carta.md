# Fase 5 — Carta editable y panel admin · Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Carta (categorías y platos) en MySQL, gestionable desde un panel `/admin` con navegación lateral, con fotos, endpoint público y PDF de/es generado desde la BD, y la carta real del restaurante cargada.

**Architecture:** Módulo `menu` en la API (routes → controller → service → repository) con schemas Zod compartidos; fotos procesadas con sharp a disco (`UPLOADS_DIR`); PDF con `@react-pdf/renderer` cacheado en memoria con ETag. En la web, shadcn/ui para el layout del panel, listados y formularios (react-hook-form + mismos schemas Zod), datos con TanStack Query.

**Tech Stack:** Express 5, Kysely + MySQL 8.4, Better Auth, Zod 4, multer, sharp, @react-pdf/renderer, React 19 + Vite 8, shadcn/ui (Tailwind v4), TanStack Query, react-hook-form, react-i18next, Vitest, Supertest, Playwright + axe.

**Spec:** [`docs/superpowers/specs/2026-11-21-fase-5-carta-design.md`](../specs/2026-11-21-fase-5-carta-design.md) · ADR [0008](../../decisions/0008-shadcn-ui.md), [0009](../../decisions/0009-menu-pdf-and-images.md)

## Global Constraints

- Rama `feat/fase-5-carta`; commits Conventional Commits en inglés con la línea `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- TypeScript strict, sin `any`. Código y nombres en inglés; textos visibles solo vía i18n (`de` y `es`).
- Todo input externo validado con Zod de `packages/shared`; errores con `AppError(status, CODE, message, details?)` → `{ error: { code, message, details } }`.
- BD: migración nueva (nunca editar la de fase 3), snake_case plural, `DATETIME(3)` UTC, `DECIMAL(10,2)` para precio.
- Estados: `visible` | `hidden` | `archived`. No hay borrado físico de categorías ni platos.
- Roles: `admin` todo; `staff` lectura + cambiar `status` de platos entre `visible`/`hidden`.
- Fotos: máx. 10 MB, WebP 400/800/1600 px, sin metadatos, nombre UUID, `Cache-Control: public, max-age=31536000, immutable`.
- `GET /api/v1/menu` y `/menu/pdf`: `Cache-Control: no-cache` + `ETag`; el resto de `/api` sigue `no-store`.
- Cierre de cada tarea: tests de esa tarea en verde + `npm run typecheck` + `npm run lint`. Cierre de fase: `npm run check:all` y `npm run db:check` en verde.

## Review Focus

1. **Precio con coma** (`12,90`) escrito en el formulario por personal alemán/español → se guarda 12.90, no NaN ni error. Test en Task 1 (schema) y Task 10 (form).
2. **Foto subida desde un móvil (HEIC/JPEG con orientación EXIF y GPS)** → se ve derecha y sin metadatos; HEIC no soportado → 415 con mensaje traducido, no 500. Test en Task 5.
3. **Categoría oculta con platos visibles** → ninguno aparece en `/menu` ni en el PDF. Test en Task 6.
4. **Textos largos con caracteres especiales (ñ, ä, ß, «», €)** → se guardan y salen bien en el PDF (fuente incrustada con esos glifos). Test en Task 6.
5. **Sesión caducada a mitad de un formulario** → al guardar, 401 lleva a `/admin/login` sin perder la ruta; no se muestra un error técnico. Test en Task 8.
